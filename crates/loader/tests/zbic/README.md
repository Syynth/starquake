# ZBIC frames from the reference encoder

Each `.zbic` file is one ZBIC frame that holds synthetic data, made by the reference's own
encoder: the zstd that Eden-NX2 compiles for `src/common/zbic_compression.cpp`, which is
`src/zstd.c` of `kinnay/zbic` @ 11b08f27 (the `zbic` entry of `eden-nx2/cpmfile.json`), built with
`ZSTD_ZBIC_SUPPORT` defined to 1. They are here so that the decompressor
(`crates/loader/src/zbic.rs`) is tested against frames that this repository's own builder did not
make. No game data is involved, and nothing of the encoder is in the repository: a frame is the
encoder's output, not its code.

The data is regenerated by the test (`sample` in `crates/loader/src/zbic/tests.rs`, which says
what each kind is), so a frame is checked against bytes that are not stored here.

| File | Data (`kind`, length, seed) | Level | Other parameters | What it is here for |
|---|---|---|---|---|
| `text_600.zbic` | `Text`, 600, 1 | 3 | | single-stream Huffman literals with FSE-compressed weights; three described sequence tables |
| `skew_200.zbic` | `Skewed`, 200, 5 | 3 | | predefined sequence tables; a one-byte content size |
| `skew_900.zbic` | `Skewed`, 900, 5 | 3 | | four-stream literals, sizes in 10 bits |
| `skew_2000.zbic` | `Skewed`, 2000, 6 | 3 | | four-stream literals, sizes in 14 bits; a two-byte sequence count |
| `runs_20k.zbic` | `Runs`, 20000, 11 | 3 | | raw literals with a two-byte header; an offset table in RLE mode |
| `zeros_300k.zbic` | `Zeros`, 300000, 10 | 3 | | RLE blocks; three blocks; a four-byte content size |
| `text_8k_tb.zbic` | `Text`, 8000, 14 | 3 | `ZSTD_c_targetCBlockSize` 300 | a second block with treeless literals and repeated tables |
| `nib_300.zbic` | `Nibbles`, 300, 15 | 3 | | Huffman weights stored directly |
| `short_20k.zbic` | `Short`, 20000, 21 | 1 | | a table description with the low-counts flag |

`the_reference_frames_hold_the_layouts_they_are_here_for` checks the last column.

## Making them again

Write the data with the generator (a 64-bit LCG, `x = x * 6364136223846793005 +
1442695040888963407`, output `x >> 33`; `sample` is the definition). Compile a program that
includes that `zstd.c` after `#define ZSTD_ZBIC_SUPPORT 1`, creates a `ZSTD_CCtx`, sets
`ZSTD_c_compressionLevel` to the level in the table (and `ZSTD_c_targetCBlockSize` where the
table says so; every other parameter is left at its default, so the frame states its content
size and has no checksum), and writes what `ZSTD_compress2` returns. That program is a dozen
lines and is not kept here: the encoder it compiles is GPL-2.0 and stays out of the repository
(the module docs of `crates/loader/src/zbic.rs` say how it is used for facts only).
